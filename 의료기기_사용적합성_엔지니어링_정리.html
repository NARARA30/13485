한눈에 보기

사용적합성(Usability)이란 의도된 사용자가 의도된 환경에서 의료기기를 효과적·효율적·만족스럽게 사용하는 특성을 말합니다. 사용적합성 엔지니어링은 사용과 관련된 위험을 완화·통제하여 안전·유효한 제품을 만드는 설계·개발 프로세스의 일부이며, 위험관리(ISO 14971)와 함께 진행됩니다.

목표정상 사용 중 발생하는 위해 관련 사용오류 발견·제거·완화 → 의료사고 최소화
핵심 도구사용 사양서 → 위해요인·사용오류 식별 → 사용 시나리오 → UI 설계 → 평가
두 평가형성평가(개발 중·개선) → 총괄평가(완료·최종 검증)
사용적합성 ≠ 사용 편의성. 편리함 추구가 아니라 사용 안전성 평가가 본질입니다.

Ⅰ. 용어의 이해

용어정의
사용적합성(Usability)의도된 사용자·환경에서 사용이 효과적·효율적·만족스러운 특성. 실제 사용자의 제품 사용으로 설계 유효성 확인.
사용자 인터페이스(UI)소리·화면·촉감·버튼·음성·지문 등 사용자와 기기 사이의 소통 수단(디스플레이·버튼·메뉴·사용설명서 포함).
PCA 모델사용자 상호작용을 지각(Perception)→인식(Cognition)→조치(Action)로 모델화. 각 단계 실패가 위해상황으로 연결.
사용적합성 평가(Usability Test)시장진입 전 제조자가 기기가 안전·유효하고 사용하기 쉽게 설계됐는지 검증.
사용적합성 엔지니어링사용 관련 위험을 완화·통제하는 설계·개발 프로세스(위험관리/설계개발 절차의 일부).
사용 오류(Use Error)제조자 의도·사용자 예상과 다른 결과를 낳는 사용자 행위 또는 행위의 생략.

제품 사용의 3분류

올바른 사용사용 오류비정상 사용
지침대로 오류 없이 사용사용자 지각·이해·행동의 오류 (예: 소리 못 들음, 결과 오해석, 부품 오연결)지침 미준수 사용 (예: 고의 파손, SW 해킹, 금기 환자 사용)

사용적합성 평가는 사용 오류(정상 사용 범위)를 다룹니다. 비정상 사용(고의)은 원칙적으로 대상 밖.

Ⅱ. 사용적합성 평가의 목적

규제 배경

  • 기술 트렌드 변화 가속, 복잡·다양한 개념의 기기 출시, UI 복잡성 증가 → 사용 오류 증가.
  • 위험기반 심사를 하는 규제당국의 사용성 위험통제 요구 강화.

정의와 목적

  • 사용적합성: 의도된 환경에서 기기 사용을 용이하게 하여 안전성·유효성·효율성·만족도를 확립하는 UI 특성. 기기의 안전성/위험도를 높이거나 낮출 수 있음.
  • 목적 = 의료사고 최소화: 정상 사용 중 발생하는 위해 관련 사용오류를 확인·발견하고, 위험관리 프로세스와 함께 개발 초기부터 제거·완화.
  • 적용 대상: 모든 전기전자 의료기기, 의료용품, 체외진단의료기기, 의료기기 소프트웨어(SaMD).
효과: 업무능률·의료서비스 품질 향상, 환자 안전·신뢰 증가, 불만·개발/유지보수 비용 감소, 법적분쟁 감소, 기업 이미지 강화.

Ⅲ. 사용적합성 엔지니어링 프로세스 (IEC 62366-1, 5.1~5.8)

설계입력 → 설계출력 → 설계검증(형성평가) → 설계 유효성 검증(총괄평가)의 V자 흐름으로 진행됩니다.

5.1 사용 사양서(Use Specification) 준비

기기 사용 관련 특성을 제조자 정의 또는 유사기기 조사로 식별. 5가지 축:

  • 무슨 사용목적으로? (진단·치료·모니터링·스크리닝)
  • 누구를 대상으로? (의료진·환자·일반; 직업·나이·지식·언어·문맹·장애·선호 등)
  • 인체 어느 부위에? (적용/상호작용 신체·조직 부위)
  • 어느 환경에서? (병원·요양원·가정; 기후·조명·소음·물리환경·방해요인)
  • 제품 동작은 어떻게? (작동원리)

5.2 안전 관련 UI 특성 및 잠재적 사용오류 식별

  • ISO 14971:2019(5.2~5.4) 위험분석의 일부로 안전 관련 UI 특성을 파악. 참고: ISO TR 24971 A.2.31~A.2.35 질문 목록(UI 설계가 사용오류 유발 가능성, 소음 환경, 알람, 이동/휴대, 필수성능 의존 등).
  • 사용오류 파악 방법: ① 태스크 분석(작동·유지·통제 활동을 순차/동시 묘사) ② 기능 분석(자동/반자동/수동 기능 구분) ③ 알려진 문제 분석(인터뷰·문헌·불만·검색으로 유사기기 장단점 연구).
  • 결과는 사용적합성 엔지니어링 파일에 문서화.

5.3 알려지거나 예측 가능한 위해요인·위해상황 파악

ISO 14971:2019(5.4~5.5) 위험분석의 일부로, 사용 사양서·식별된 사용오류·유사기기 정보를 고려해 위해요인·위해상황을 파악. 이 과정에서 비정상 사용도 파악될 수 있음.

5.4·5.5 위해 관련 사용 시나리오 파악 및 선정

  • 위해요인·위해상황과 관련된 합리적으로 예측 가능한 사용 시나리오를 파악·설명(작업·순서 + 위해 심각도 포함).
  • 총괄평가용 시나리오 선택: 심각도·발생빈도 기반, 위험도 높은 시나리오 우선. 1회 이상 발생한 사용오류는 반드시 반영. 모든 태스크를 시나리오화할 필요는 없음.

5.6 사용자 인터페이스 사양서 수립

  • UI 설계 전, 사용 사양서·예측 가능한 사용오류·위해 관련 시나리오를 고려해 작성.
  • 포함: 시험 가능한 기술 요구사항, UI 시안, 사용 교육 필요성 정의, 관련 문서. (엔지니어링 파일에 저장/통합)

5.7 사용자 인터페이스 평가 계획 수립

형성·총괄평가 계획 수립(시험 목적·범위, 대상자·진행자·관찰자 선정, 태스크·평가방법, 환경·일정, 설문/기록 양식, 비밀유지·촬영동의, 결과분석 방법).

5.8 UI 설계 · 형성평가 · 총괄평가 수행

  • UI 설계 후 형성평가(예: 인지사찰법) → 개선 필요/신규 문제 시 반복.
  • 이후 총괄평가(구현평가/시뮬레이션, 의도된 사용자 15명 내외, 실제/유사 환경, 진행자·관찰자 분리, 전 과정 녹화·녹취) → 신규 문제/개선 필요 시 재수행.
  • 데이터 분석: 응답자·관찰자 평가, 발생 오류 심각도, 그룹/제품 간 비교, 통계 기법으로 최종 분석. 설계 변경은 위험관리 파일에 반영·업데이트.
총괄평가 핵심: UI 안전을 확증하는 최종 단계. 예상·비예상 치명적(critical) 사용오류가 없음을 확인해야 통과.

사용적합성 엔지니어링 파일 (산출물 종합)

프로세스 산출물을 근거로, 사용설명서를 바탕으로 의도된 사용자 집단이 제조자 의도대로 작동 가능하고, 사용오류로 인한 위험이 허용 가능하며, UI·제공문서가 유효하게 작용하여 사용목적을 달성할 수 있음을 종합 평가·입증하는 파일.
